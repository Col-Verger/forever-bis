# Планы развития

Коротко: сайт остаётся «пререйд-BiS Фазы 1» до тех пор, пока симулятор не даст данные
для следующей фазы. Ниже — что именно делать, когда это случится, и почему.

## 1. Следующие фазы

Принцип: **одна страница, переключатель фазы**. Каждый сет хранит свою фазу, поэтому
разные фазы можно обновлять независимо и честно показывать даты.

### Данные

1. В `configs/<класс>.json` добавить `"phase": 1` (у билда можно переопределить).
   Сейчас все конфиги — Фаза 1.
2. `configs/pools/*.json` уже поддерживают `phaseMax` (`tools/make_pools.py`):
   для Фазы 1 стоит 1, для Фазы 2 — 2. В базе сима сейчас 6598 предметов фазы 1
   и 817 фазы 2 (PvP-ранги, Ashbringer и т.п.) — фильтр просто поднимется.
3. Прогоны: `runs/p<phase>/<id>-<budget>.*`. Старые плоские файлы читаются как Фаза 1,
   чтобы ничего не переименовывать задним числом.
4. `data.js`: у сета появляется `phase`, у спека — список доступных фаз, в `meta` —
   дата по каждой фазе. Спеки сортируются по числам внутри своей фазы.

### Интерфейс

- Селектор фазы в шапке (Пре-рейд / Фаза 1 / Фаза 2), состояние в URL: `&phase=2`.
- «Сеты класса», «План одевания», фильтр и матрица работают в рамках выбранной фазы.
- Вкладка «Данные» показывает свежесть по каждой фазе отдельно.
- Если для выбранной фазы у спека нет прогона — честная плашка «ещё не просчитано»,
  а не подстановка чисел другой фазы.

### Ссылки и SEO

- Статические страницы: `spec/<phase>/<cls>/<spec>/`; пре-рейд остаётся корнем
  (`spec/<cls>/<spec>/`), чтобы не ломать уже проиндексированные адреса.
- `canonical` и `sitemap.xml` — по каждой фазе; в `<title>` фаза указывается явно.

### Что уже готово со стороны симулятора

- Наборы снаряжения следующих фаз в репозитории уже есть (`gear_sets/p1_*` у воинов,
  пресеты вида `P1` у друидов и т.д.) — новые билды добавляются как обычные строки
  в `builds`, без переписывания пайплайна.
- Чего нет: ротаций/билдов для фаз могут не быть сразу. Тогда фаза просто не
  появляется на сайте — как сейчас с хилами.

## 2. Хилы и HPS

**Факт на сегодня:** у хил-спеков в симуляторе есть таланты, снаряжение и веса статов,
но **нет ротаций**. В `ui/specs/priest/healer/spec.ts` стоит `enableHealing: true`,
а рядом комментарий «Not used until healing sim available»; тест хил-приста считает
только статы с пустой APL. Пустая ротация = ноль исцеления, поэтому HPS-чисел нет.

**Что делаем сейчас:** хил-сеты берём из гайдов Wowhead и помечаем бейджем — это уже работает.

**Когда симулятор добавит ротации:**

1. Добавить билды с `"metric": "hps"` (драйвер уже пишет `hps`, интерфейс уже умеет
   показывать HPS вместо DPS).
2. Проверить на одном спеке: осмысленный HPS, ненулевые статы, ссылка в WoWSims
   открывает тот же бой.
3. Убедиться, что сортировка не смешивает метрики: DPS-спеки идут по убыванию DPS,
   HPS-спеки — отдельной группой после них (сейчас хил-спеки просто в конце).
4. Сет из Wowhead заменится симмированным автоматически — правило приоритета уже
   зашито в `build_data.py`.

**Как не пропустить момент:** добавить в CI шаг, который раз в сутки проверяет,
появились ли у хил-спеков `defaults.siml`/APL, и пишет об этом в лог прогона
(и, по желанию, в issue). Это дешевле, чем регулярно смотреть вручную.

## 3. Дальше по приоритету

1. **«Мой сет»** — отметить имеющиеся предметы из уже измеренных вариантов, получить
   «следующий апгрейд» и Δ до BiS. Без импорта аддонов и без выдуманных чисел.
2. **Ссылка на свой набор** — сохранить примерку в URL и отправить в дискорд.
3. **EN-версии статических страниц** — сейчас страницы для поиска русские; EN-аудитория
   у Forever тоже есть.
4. **Картинка превью** для Discord/Telegram (сейчас превью текстовое).
5. **Search Console и Яндекс.Вебмастер** — подтверждение и отправка `sitemap.xml`,
   затем внешние ссылки (Discord/Reddit/комментарии гайдов).

## 4. Ограничения, о которых помним

- Каждое число — реальный прогон; нет прогона — нет числа.
- Примерка и «мой сет» считаются из измеренных замен, поэтому не покрывают произвольную
  зелёнку и предметы вне пула.
- Публикация терпит частичный прогон: класс, который не успел, остаётся на прошлых
  числах со своей датой.
