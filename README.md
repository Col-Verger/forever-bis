# Pre-Raid BiS · WoW Forever — все классы

Пререйд-BiS гайд **по всем 9 классам** для **WoW Forever, Фаза 1** — по образцу
[Forever Hunter guide](https://toxickevinferm.github.io/hunter-guide/prebis-new/).

**Сайт: https://col-verger.github.io/forever-bis/** · репозиторий: [Col-Verger/forever-bis](https://github.com/Col-Verger/forever-bis)

Для каждого спека страница показывает: лучший сет (**Максимум** и **Дёшево** — переключатель
бюджета), каждую опцию каждого слота с её отставанием от лучшей (± погрешность сима),
источник каждого предмета и сравнение всех сетов бок о бок.

Сейчас в данных: **30 симмированных билдов × 2 бюджета = 60 сетов** + 3 хил-сета по гайдам
Wowhead (см. ниже) = **63 сета**, около **900 предметов** с русскими названиями из Wowhead RU
и русскими строками «где достать» (зоны, NPC, квесты — тоже из Wowhead RU).

## Честная политика данных

На странице нет ни одного придуманного числа. Каждая цифра — результат реального прогона
WoWSims Forever; в шапке и на вкладке «Данные» прошиты дата прогона и хеш коммита симулятора.

**Хил-спеки.** Симулятор WoWSims Forever пока не выпустил для них ни ротаций (APL),
ни дефолтных настроек — поэтому симмировать их нечем. Для трёх спеков сет взят из
**гайдов Wowhead Forever** и помечен на сайте бейджем «Wowhead-гайд»:

| Спек | Источник | Состояние |
|---|---|---|
| Рестор-шаман | [гайд Wowhead](https://www.wowhead.com/forever/guide/classes/shaman/restoration/bis-gear) | 17 слотов, без Δ-чисел |
| Рестор-друид | [гайд Wowhead](https://www.wowhead.com/forever/guide/classes/druid/restoration/bis-gear) | 17 слотов, без Δ-чисел |
| Хил-прист | [гайд Wowhead (Holy)](https://www.wowhead.com/forever/guide/classes/priest/holy/bis-gear) | 16 слотов, без Δ-чисел |
| Holy-паладин | — | гайд Wowhead пуст → «ждёт пресет» |

Правило приоритета жёсткое: **симы всегда побеждают Wowhead**. Как только у спека
появятся прогоны (`runs/<спек>-max.json`), `build_data.py` собирает сет из них, а
фолбэк-файл для этого спека перестаёт использоваться — без правок кода и данных.

## Как это устроено (архитектура)

Сайт **не** гоняет симы сам: wowsims.com — это WASM-приложение в браузере, живого API у него
нет. Числа приносит пайплайн в GitHub Actions:

```
wowsims/forever (master)                 этот репозиторий
────────────────────────                 ─────────────────
ui/specs/…        пресеты билдов    ┌──────────────────────────────────────┐
assets/database/db.json             │ resim.yml (ежедневно, 04:00 UTC)     │
      │            база предметов   │ 1. go build ./cmd/wowsimcli           │
      └──────────►│ 2. tools/make_pools.py  → configs/pools/*.json       │
                   │ 3. tools/run_sims.py    → runs/*.json                │
                   │ 4. tools/build_data.py  → data.js (+ аудит)          │
                   │ 5. tools/make_pages.py  → spec/, sitemap.xml         │
                   └───────────────┬──────────────────────────────────────┘
                                   ▼
                     index.html + assets/app.js (GitHub Pages)
                     каждая цифра = сим из шага 3, версия сима = шаг 1
```

Четыре способа ingestion билдов (все — в `configs/<класс>.json`):

- **`buildJson`** — готовый build-файл сима: **пять варлоков** (Aff Wrack, Demo Fire Brand,
  Demo Shadow Brand, Destro, SM/Ruin), **два приста** (Shadow Testing, Smite) и шаман
  (Elemental, Enhancement);- **`presetBuild`** — готовый пресет симулятора в `.siml`. Драйвер раскрывает
  `defaults.siml` спека вместе со всеми его обычными включениями (например, `buffs.siml`),
  склеивает слои (поздний ключ перекрывает ранний, как в UI симулятора), выбрасывает
  их `gear`/APL-включения и подставляет наши пул, APL, итерации и босса. Текст пресета
  не перепечатывается, поэтому изменения в репозитории сима доезжают до следующего
  прогона сами. Так собраны **пять билдов охотника** (BM, MM, SV, SV weave, SV melee)
  и **два билда ретри-паладина** (Unsealed Wrath, Holy Shock) — ровно те пресеты, что
  есть в WoWSims Forever. Пропавший файл пресета не подменяется молча: билд помечается
  как непросчитанный, а остальные билды класса продолжают считаться;
- **транскрипция `presets.ts`** — таланты/бафы/расходники переписаны из UI-пресетов
  (маг, друид, воин, рог);
- **`.siml`-шаблон** — полный setup-файл, драйвер меняет только секцию `gear`
  (прот-паладин).

## Автоматическое обновление

- **`resim.yml`** — полный пересчёт по расписанию **каждый день в 04:00 UTC** (`0 4 * * *`)
  и по кнопке. Каждый класс и бюджет идут отдельной джобой матрицы (18 джоб), публикация —
  отдельной джобой. Полный пересчёт ≈ 1–2 часа, и тяжёлый класс больше не
  упирается в общий лимит времени.
- Джоба класса и бюджета ограничена 300 минутами; если она всё же не успела,
  остальные классы публикуются, а этот остаётся на прошлых числах со своей датой.
- Один сломанный билд больше не роняет весь класс и публикацию: драйвер пишет
  `runs/<билд>.status.json` с причиной, класс досчитывается, на сайте у билда честная
  плашка «не просчитался в последнем обновлении».
- Публикация забирает то, что успело пересчитаться: класс, у которого джоба упала или
  не уложилась в лимит, остаётся на своих прошлых прогонах, а остальные обновляются.
- При падении прогона автоматически открывается issue «Прогон не удался» (или
  комментарий в открытую), со ссылкой на запуск. Сбой виден без наблюдателя.
- Перезапустить можно один класс и один бюджет: входы `only_class` и `budget`.
  Даты у каждого сета свои, поэтому «свежий» сайт не выдаёт старые числа за новые.
- **`deploy.yml`** — мгновенная публикация статики без симов (когда менялись только
  `index.html`/`assets/*`/`data.js`). Считает хеши `app.js`/`style.css` для cache-busting.

Посетителю ничего делать не нужно: сайт всегда показывает последний прогон.

## Запуск локально (Windows/Linux)

Требуется: Go 1.24+, Python 3.10+, git, protoc (генератор protobuf).

```powershell
git clone --depth 1 https://github.com/wowsims/forever ../forever

# proto-пакеты сима — генерируемый код (один раз после клона/обновления)
go install google.golang.org/protobuf/cmd/protoc-gen-go@latest
cd ../forever
protoc -I=./proto `
  --go_opt=Mgoogle/protobuf/descriptor.proto=google.golang.org/protobuf/types/descriptorpb `
  --go_out=./sim/core ./proto/*.proto

# CLI с встроенной базой предметов (--tags=with_db обязателен)
go build --tags=with_db -o ../wowsimcli.exe ./cmd/wowsimcli
cd ..

# 1. сгенерировать пулы кандидатов (пересматриваемый configs/pools/*.json)
python tools/make_pools.py --forever forever --configs configs

# 2. прогнать пер-слотовые поиски → runs/
python tools/run_sims.py --forever forever --wowsimcli wowsimcli.exe --configs configs --out runs
#    один спек / один бюджет:  --only druid-feralcat --budgets cheap

# 3. собрать data.js (аудит данных печатается в конце)
python tools/build_data.py --forever forever --runs runs --configs configs --out data.js `
  --commit $(git -C forever rev-parse --short HEAD) --repo "Col-Verger/forever-bis"

# 4. статические страницы спеков и sitemap.xml для поисковиков
python tools/make_pages.py --data data.js --out .

# 5. открыть сайт
python -m http.server 8000   # → http://localhost:8000
```

Первый полный прогон — самый долгий. Ускорить: `--only mage-arcane`, `--search-iterations 1500`,
`--jobs 3`. Проверка форматов без симов: `--dry-run`; одиночный базовый сим: `--validate`.

## Видимость в поиске (SEO)

Основная страница — одностраничное приложение с хеш-маршрутами (`#tab=gear&cls=…`).
Поисковики считают хеш частью одного URL, поэтому одного приложения мало: у каждого спека
есть **настоящая страница** `spec/<класс>/<спек>/` — статический HTML с заголовком,
описанием, полным BiS-сетом, статами и источниками. Их собирает `tools/make_pages.py`
из `data.js` на каждом прогоне; ссылки на них — в `spec/` и в подвале главной.

- `robots.txt` — разрешает индексацию и указывает на `sitemap.xml`;
- `sitemap.xml` — главная, список спеков и все страницы спеков с датой прогона;
- на каждой странице: `title`, `description`, `canonical`, Open Graph, JSON-LD (`WebPage`),
  `lang="ru"`, ссылки на интерактивную версию и WoWSims;
- `404.html` — для несуществующих путей (GitHub Pages отдаёт его сам).

**Домен.** Бесплатный адрес GitHub Pages — только `*.github.io`; `*.github.com` — это сам
GitHub, там хостить нельзя, а произвольный поддомен вида `bis.col-verger.github.io` GitHub
не выдаёт. Варианты: оставить `https://col-verger.github.io/forever-bis/`, сделать
пользовательский сайт `col-verger.github.io` (репозиторий с таким именем) или подключить
**свой домен**: файл `CNAME` в корне, DNS `CNAME` на `col-verger.github.io` (для апекса —
A-записи GitHub), затем Settings → Pages → Custom domain и «Enforce HTTPS». Сертификат
Let's Encrypt GitHub выдаёт сам.

**Что ещё нужно для реальной видимости.** Индексация — не то же самое, что позиции:
после выкладки стоит добавить сайт в Google Search Console и Яндекс.Вебмастер (подтверждение
мета-тегом или DNS), отправить `sitemap.xml`, а ссылки на сайт — в профильные Discord/Reddit
и комментарии гайдов. Свежесть (ежедневные прогоны) и уникальные проверяемые числа — наши
главные аргументы; без внешних ссылок новый сайт в выдачу почти не попадает.

## Аудит данных

`tools/build_data.py` в конце каждого прогона вызывает `tools/audit_data.py` и печатает
найденные дефекты (`audit: N problems, M notes`). Проверяется:

- пустой слот, хотя в пуле были кандидаты;
- один и тот же уникальный предмет в двух слотах (например, кольцо в обоих пальцах);
- нулевые/отсутствующие значения и Δ;
- отсутствующие таланты у симмированного спека;
- ссылки на предметы, которых нет в базе сима;
- цвет качества: `q` каждого предмета в `data.js` сверяется с `quality` в базе симулятора,
  а палитра `--q0…--q5` в `style.css` — с каноническими цветами WoW (эпик фиолетовый,
  редкий синий, обычный зелёный и т.д.);
- выгрузка статов: у каждого прогона со `settings.json` есть непустой `stats.json`
  (статы считает сам сим через `ComputeStats`);
- энчанты: у каждого энчанта с собственными статами, который встречается в сетах или
  в вариантах примерки, есть запись в `data.js` — иначе дельта примерки молча
  занижала бы изменение.

Запустить отдельно: `python tools/audit_data.py --runs runs --configs configs`
(пишет `runs/_audit.json`). Сборка при problems не падает — дефекты видны в логе Actions,
и это повод перегнать конкретный спек (`--only <спек>`), а не публиковать как есть.

## Бюджеты «Максимум» и «Дёшево»

- **Максимум** — весь пул кандидатов, включая PvP Premier, репутацию Revered/Exalted и
  дорогие эпик-крафты.
- **Дёшево** — только свободнодоступное: без PvP-гринда, без высокой репутации, без дорогих
  крафтов. База сета освобождается от «дорогих» предметов, и поиск заново заполняет слоты
  из дешёвого пула.

Поэтому сеты отличаются на **2–9 слотов** — это дизайн, а не рассинхрон: в фазе 1
max-сеты как раз и держатся на PvP/репутации/крафтах.

Разметка «дорогого» — правило `item_tier` в `tools/make_pools.py`; спорный предмет
переносится в конфиге спека через `excludeIds`/`includeIds`.

## Добавить класс / спек / билд

1. В `configs/<класс>.json` — секция `builds` (четыре режима см. в архитектуре).
   Для пресета симулятора достаточно `"presetBuild": "builds/<файл>.siml"` + `apls` +
   `baseGear` — остальное соберётся из `defaults.siml` при прогоне.
2. Правила пула в `pools` того же файла (тип брони, типы оружия, фильтры).
3. `python tools/make_pools.py ...`, затем `--validate` для нового билда — и либо локальный
   прогон, либо просто запустить `resim.yml` (пересчитает всё).
4. Хил-спеку без симов достаточно добавить кандидатов в `tools/wowhead_bis.json`
   (слот → список ID по убыванию приоритета); `build_data.py` возьмёт первый предмет,
   чей тип в базе сима совпадает со слотом.

## Пулы кандидатов (важно!)

`tools/make_pools.py` предлагает кандидатов по правилам из `configs/*.json`
(ткань/плиты, типы оружия, качество, «не из рейдовых зон») и пишет их в
`configs/pools/<prefix>.pools.json` — файл с именами и источниками для просмотра.
**Пул — это редакторское решение**, как и у автора хантер-гайда: посмотри сгенерированный
файл, поправь `includeIds`/`excludeIds` в конфиге спека и закоммить. Симы ранжируют только
то, что в пуле. В каждом пуле всегда остаётся дешёвый срез (до 8 предметов), чтобы
max-предметы не вытеснили дешёвых кандидатов.

## Интерфейс

- RU/EN переключатель; названия предметов — русские из Wowhead RU, ссылки — `/forever/ru/item=<id>`,
  поиск — `/forever/ru/search?q=`, таланты — `/forever/ru/talent-calc/...`.
- Строки «где достать» тоже двуязычные: зоны, NPC и квесты переводятся через Wowhead RU
  (кэш `tools/ru_geo.json`), фракции и уровни репутации — таблицей в `tools/build_data.py`.
  Если Wowhead не знает русского имени, строка честно остаётся английской, а не подменяется.
- Тема в цветах класса, иконка класса, матрица «Сеты класса», график важности слотов,
  тултипы, умный фильтр (подсказки из реальных предметов) и фильтры по источнику.
- Клик по строке варианта «примеряет» предмет: кукла переодевается, а число наверху
  становится оценкой сборки (`≈`) — суммой измеренных вкладов замен. Бонусы комплектов
  и точное число даёт только новый прогон, о чём страница честно пишет. Набор замен
  сохраняется в браузере отдельно для каждого сета; после обновления данных замены,
  которых больше нет в вариантах, отбрасываются, чтобы оценка не врала.
- Кнопка «Открыть сет в WoWSims» ведёт на готовый сет с этим снаряжением, талантами
  и боссом (для своей сборки — «Открыть BiS-сет»).
- Под кнопкой — **статы сета из симулятора** (снаряжение + энчанты + таланты + бафы +
  расходники): сила заклинаний/атаки, меткость, крит, броня, выживаемость и т.д. На время
  примерки они остаются (это статы BiS-сета), а под ними появляется строка **изменения от
  примерки** — построчная разница статов предметов и энчантов с пометкой, что бонусы
  комплектов и эффекты (прожи) в неё не входят.
- Кнопка «Наверх» в правом нижнем углу возвращает к началу страницы.
- Спеки в переключателе и в матрице «Сеты класса» идут **от лучшего числа к худшему**
  (по «Максимуму»); спеки без прогона — в конце. Сортировка берётся из самих симов,
  а не из порядка в конфиге.
- Вкладка «План одевания» — весь BiS-сет чек-листом, сгруппированный по источникам:
  подземелье, квесты, репутация, крафт, продавцы, PvP, мировой дроп — плюс список энчантов.
  Есть фильтры: чипы по источникам, «только не собранное» и поиск по предмету/источнику.
  Отметки «уже есть» хранятся только в браузере (localStorage) и никуда не отправляются;
  рядом прогресс «собрано N из M», кнопки «Скопировать список» (для дискорда) и «Сбросить».
  План всегда для текущего спека и бюджета — они переключаются сверху.
- Вкладка «Данные»: последнее обновление (дата/время UTC + коммит сима), объяснение
  пайплайна и как читать числа. На карточке сета — дата именно его прогона
  («Прогон этого сета»), а не только общая дата сайта. Никаких «обновите у себя» —
  обновление ежедневное и автоматическое.

## Структура

```
index.html                      страница (RU/EN в шапке)
assets/app.js                   рендер: кукла, карточки слотов с Δ и ±, матрица, тултипы
assets/style.css                раскладка, темы классов, шрифты
data.js                         ГЕНЕРИРУЕТСЯ tools/build_data.py — руками не править
configs/<класс>.json            билды (builds) + правила пулов (9 файлов)
configs/pools/                  материализованные пулы (make_pools.py)
tools/run_sims.py               драйвер: per-slot поиск через wowsimcli → runs/*.json
tools/make_pools.py             генератор пулов из assets/database/db.json
tools/build_data.py             склейка runs + db.json → data.js, RU-имена, аудит
tools/make_pages.py             статические страницы спеков + sitemap.xml (SEO)
spec/                           ГЕНЕРИРУЕТСЯ make_pages.py — страницы спеков для поиска
sitemap.xml, robots.txt, 404.html  индексация и обработка несуществующих путей
tools/audit_data.py             проверка дефектов данных (пустые слоты, дубли, нули)
tools/linkhash/                 IndividualSimSettings → ссылка-шар «открыть сет в WoWSims» (Go)
tools/make_links.py             проставляет такие ссылки в runs/*.meta.json
tools/statdump/                 статы персонажа из сима (ComputeStats) → runs/<спек>.stats.json
tools/make_stats.py             досчитывает stats.json для готовых прогонов
tools/spec_routes.py            маршрут страницы спека в UI симулятора (для ссылок)
tools/wowhead_bis.json          BiS хил-спеков из гайдов Wowhead (фолбэк до симов)
tools/ru_names.json             кэш русских названий предметов
tools/ru_geo.json               кэш русских названий зон, NPC и квестов (Wowhead RU)
```
