# Pre-Raid BiS · WoW Forever — все классы

Пререйд-BiS гайд **по всем 9 классам** для **WoW Forever, Фаза 1** — по образцу
[Forever Hunter guide](https://toxickevinferm.github.io/hunter-guide/prebis-new/).

**Сайт: https://col-verger.github.io/forever-bis/** · репозиторий: [Col-Verger/forever-bis](https://github.com/Col-Verger/forever-bis)

Для каждого спека страница показывает: лучший сет (**Максимум** и **Дёшево** — переключатель
бюджета), каждую опцию каждого слота с её отставанием от лучшей (± погрешность сима),
источник каждого предмета и сравнение всех сетов бок о бок.

Сейчас в данных: **18 симмированных спеков × 2 бюджета = 36 сетов** + 3 хил-сета по гайдам
Wowhead (см. ниже) = **39 сетов**, около **970 предметов** с русскими названиями из Wowhead RU.

## Честная политика данных

На странице нет ни одного придуманного числа. Каждая цифра — результат реального прогона
WoWSims Forever; в шапке и на вкладке «Данные» прошиты дата прогона и хеш коммита симулятора.

**Хил-спеки.** Симулятор WoWSims Forever пока не выпустил для них ни ротаций (APL),
ни дефолтных настроек — поэтому симмировать их нечем. Для трёх спеков сет взят из
**гайдов Wowhead Forever** и помечен на сайте бейджем «Wowhead-гайд»:

| Спек | Источник | Состояние |
|---|---|---|
| Рестор-шаман | [гайд Wowhead](https://www.wowhead.com/forever/guide/classes/shaman/restoration/bis-gear) | 17 слотов, без Δ-чисел |
| Рестор-друид | [гайд Wowhead](https://www.wowhead.com/forever/guide/classes/druid/restoration/bis-gear) | 17 слотов, без Δ-чисел |
| Хил-прист | [гайд Wowhead (Holy)](https://www.wowhead.com/forever/guide/classes/priest/holy/bis-gear) | 16 слотов, без Δ-чисел |
| Holy-паладин | — | гайд Wowhead пуст → «ждёт пресет» |

Правило приоритета жёсткое: **симы всегда побеждают Wowhead**. Как только у спека
появятся прогоны (`runs/<спек>-max.json`), `build_data.py` собирает сет из них, а
фолбэк-файл для этого спека перестаёт использоваться — без правок кода и данных.

## Как это устроено (архитектура)

Сайт **не** гоняет симы сам: wowsims.com — это WASM-приложение в браузере, живого API у него
нет. Числа приносит пайплайн в GitHub Actions:

```
wowsims/forever (master)                 этот репозиторий
────────────────────────                 ─────────────────
ui/specs/…        пресеты билдов    ┌──────────────────────────────────────┐
assets/database/db.json             │ resim.yml (ежедневно, 04:00 UTC)     │
      │            база предметов   │ 1. go build ./cmd/wowsimcli           │
      └──────────►│ 2. tools/make_pools.py  → configs/pools/*.json       │
                   │ 3. tools/run_sims.py    → runs/*.json                │
                   │ 4. tools/build_data.py  → data.js (+ аудит)          │
                   └───────────────┬──────────────────────────────────────┘
                                   ▼
                     index.html + assets/app.js (GitHub Pages)
                     каждая цифра = сим из шага 3, версия сима = шаг 1
```

Три способа ingestion билдов (все — в `configs/<класс>.json`):

- **`buildJson`** — готовый build-файл сима (варлок, шаман, прист);
- **транскрипция `presets.ts`** — таланты/бафы/расходники переписаны из UI-пресетов
  (маг, друид, воин, прист, рог);
- **`.siml`-шаблон** — полный setup-файл, драйвер меняет только секцию `gear`
  (хантер, паладины).

## Автоматическое обновление

- **`resim.yml`** — полный пересчёт по расписанию **каждый день в 04:00 UTC** (`0 4 * * *`)
  и по кнопке. Классы идут параллельной матрицей (одна джоба на класс), публикация —
  отдельной джобой. Полный пересчёт ≈ 40–80 минут.
- **`deploy.yml`** — мгновенная публикация статики без симов (когда менялись только
  `index.html`/`assets/*`/`data.js`). Считает хеши `app.js`/`style.css` для cache-busting.

Посетителю ничего делать не нужно: сайт всегда показывает последний прогон.

## Запуск локально (Windows/Linux)

Требуется: Go 1.24+, Python 3.10+, git, protoc (генератор protobuf).

```powershell
git clone --depth 1 https://github.com/wowsims/forever ../forever

# proto-пакеты сима — генерируемый код (один раз после клона/обновления)
go install google.golang.org/protobuf/cmd/protoc-gen-go@latest
cd ../forever
protoc -I=./proto `
  --go_opt=Mgoogle/protobuf/descriptor.proto=google.golang.org/protobuf/types/descriptorpb `
  --go_out=./sim/core ./proto/*.proto

# CLI с встроенной базой предметов (--tags=with_db обязателен)
go build --tags=with_db -o ../wowsimcli.exe ./cmd/wowsimcli
cd ..

# 1. сгенерировать пулы кандидатов (пересматриваемый configs/pools/*.json)
python tools/make_pools.py --forever forever --configs configs

# 2. прогнать пер-слотовые поиски → runs/
python tools/run_sims.py --forever forever --wowsimcli wowsimcli.exe --configs configs --out runs
#    один спек / один бюджет:  --only druid-feralcat --budgets cheap

# 3. собрать data.js (аудит данных печатается в конце)
python tools/build_data.py --forever forever --runs runs --configs configs --out data.js `
  --commit $(git -C forever rev-parse --short HEAD) --repo "Col-Verger/forever-bis"

# 4. открыть сайт
python -m http.server 8000   # → http://localhost:8000
```

Первый полный прогон — самый долгий. Ускорить: `--only mage-arcane`, `--search-iterations 1500`,
`--jobs 3`. Проверка форматов без симов: `--dry-run`; одиночный базовый сим: `--validate`.

## Аудит данных

`tools/build_data.py` в конце каждого прогона вызывает `tools/audit_data.py` и печатает
найденные дефекты (`audit: N problems, M notes`). Проверяется:

- пустой слот, хотя в пуле были кандидаты;
- один и тот же уникальный предмет в двух слотах (например, кольцо в обоих пальцах);
- нулевые/отсутствующие значения и Δ;
- отсутствующие таланты у симмированного спека;
- ссылки на предметы, которых нет в базе сима.

Запустить отдельно: `python tools/audit_data.py --runs runs --configs configs`
(пишет `runs/_audit.json`). Сборка при problems не падает — дефекты видны в логе Actions,
и это повод перегнать конкретный спек (`--only <спек>`), а не публиковать как есть.

## Бюджеты «Максимум» и «Дёшево»

- **Максимум** — весь пул кандидатов, включая PvP Premier, репутацию Revered/Exalted и
  дорогие эпик-крафты.
- **Дёшево** — только свободнодоступное: без PvP-гринда, без высокой репутации, без дорогих
  крафтов. База сета освобождается от «дорогих» предметов, и поиск заново заполняет слоты
  из дешёвого пула.

Поэтому сеты отличаются на **2–9 слотов** — это дизайн, а не рассинхрон: в фазе 1
max-сеты как раз и держатся на PvP/репутации/крафтах.

Разметка «дорогого» — правило `item_tier` в `tools/make_pools.py`; спорный предмет
переносится в конфиге спека через `excludeIds`/`includeIds`.

## Добавить класс / спек / билд

1. В `configs/<класс>.json` — секция `builds` (три режима см. в архитектуре).
2. Правила пула в `pools` того же файла (тип брони, типы оружия, фильтры).
3. `python tools/make_pools.py ...`, затем `--validate` для нового билда — и либо локальный
   прогон, либо просто запустить `resim.yml` (пересчитает всё).
4. Хил-спеку без симов достаточно добавить кандидатов в `tools/wowhead_bis.json`
   (слот → список ID по убыванию приоритета); `build_data.py` возьмёт первый предмет,
   чей тип в базе сима совпадает со слотом.

## Пулы кандидатов (важно!)

`tools/make_pools.py` предлагает кандидатов по правилам из `configs/*.json`
(ткань/плиты, типы оружия, качество, «не из рейдовых зон») и пишет их в
`configs/pools/<prefix>.pools.json` — файл с именами и источниками для просмотра.
**Пул — это редакторское решение**, как и у автора хантер-гайда: посмотри сгенерированный
файл, поправь `includeIds`/`excludeIds` в конфиге спека и закоммить. Симы ранжируют только
то, что в пуле. В каждом пуле всегда остаётся дешёвый срез (до 8 предметов), чтобы
max-предметы не вытеснили дешёвых кандидатов.

## Интерфейс

- RU/EN переключатель; названия предметов — русские из Wowhead RU, ссылки — `/forever/ru/item=<id>`,
  поиск — `/forever/ru/search?q=`, таланты — `/forever/ru/talent-calc/...`.
- Тема в цветах класса, иконка класса, матрица «Сеты класса», кнопка «Скопировать сет»,
  график важности слотов, тултипы, поиск и фильтры по источнику.
- Вкладка «Данные»: последнее обновление (дата/время UTC + коммит сима), объяснение
  пайплайна и как читать числа. Никаких «обновите у себя» — обновление ежедневное и автоматическое.

## Структура

```
index.html                      страница (RU/EN в шапке)
assets/app.js                   рендер: кукла, карточки слотов с Δ и ±, матрица, тултипы
assets/style.css                раскладка, темы классов, шрифты
data.js                         ГЕНЕРИРУЕТСЯ tools/build_data.py — руками не править
configs/<класс>.json            билды (builds) + правила пулов (9 файлов)
configs/pools/                  материализованные пулы (make_pools.py)
tools/run_sims.py               драйвер: per-slot поиск через wowsimcli → runs/*.json
tools/make_pools.py             генератор пулов из assets/database/db.json
tools/build_data.py             склейка runs + db.json → data.js, RU-имена, аудит
tools/audit_data.py             проверка дефектов данных (пустые слоты, дубли, нули)
tools/wowhead_bis.json          BiS хил-спеков из гайдов Wowhead (фолбэк до симов)
tools/ru_names.json             кэш русских названий предметов
tools/icons.json                кэш иконок
runs/                           результаты прогонов (коммитится для прозрачности)
.github/workflows/resim.yml     ежедневный полный пересчёт (04:00 UTC)
.github/workflows/deploy.yml    мгновенная публикация статики
```
